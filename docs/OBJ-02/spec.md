## 1. Scope & System Constraints

### 1.1 Path Formatting & Shell Execution Invariants
- All file paths in configuration files, scripts, metadata, change records, rules, and documentation MUST strictly use forward-slash format (e.g., [frameworks/openspec](file:///d:/dev/agy-os/frameworks/openspec), [harness/patches](file:///d:/dev/agy-os/frameworks/openspec/harness/patches/), [harness/agy-script](file:///d:/dev/agy-os/harness/agy-script/)). Windows backslashes (`\`) are strictly prohibited in metadata, paths, and documentation instructions to prevent cross-platform tool and regex failures.
- Terminal Execution Environment: All script executions, shell commands, and automated tooling MUST strictly run using **Git Bash** (`bash`). Running scripts via CMD or PowerShell is strictly prohibited.

### 1.2 Target Repository & Upstream Isolation Boundaries
- Upstream [ECC](file:///d:/dev/agy-os/ECC) directory is treated strictly as a READ-ONLY reference library.
- Target repository [website](file:///d:/CLAUDE-PROJECT/website) (`d:/CLAUDE-PROJECT/website`) is strictly READ-ONLY. Direct writes, edits, file creations, or folder deletions within the target repository are strictly forbidden.
- All proposed target modifications, fixes, or feature additions generated by OpenSpec workflows MUST be produced as `.patch` or `.diff` files and staged in [frameworks/openspec/harness/patches/](file:///d:/dev/agy-os/frameworks/openspec/harness/patches/) or root [harness/patches/](file:///d:/dev/agy-os/harness/patches/).
- All custom installer scripts, adapters, and entrypoints MUST reside under [harness/agy-script/](file:///d:/dev/agy-os/harness/agy-script/).

### 1.3 Documentation Hierarchy & SSOT Invariants
- Exactly ONE Single Source of Truth global PRD exists at [docs/PRD.md](file:///d:/dev/agy-os/docs/PRD.md).
- Objective suite directories under [docs/](file:///d:/dev/agy-os/docs/) (such as [docs/OBJ-02/](file:///d:/dev/agy-os/docs/OBJ-02/)) MUST consist strictly of `spec.md`, `design.md`, `task.md`, and `artifacts/`. Creating `PRD.md` or `prompt.md` files inside any `docs/OBJ-XX/` directory is strictly prohibited.

## 2. Requirements

### Requirement: Custom ECC Installation for Harness
<!-- id: harness.ecc.custom_installation -->
<!-- entities: HarnessInstaller, ECCPluginOverlay -->
<!-- enforced: harness/agy-script/install-agy.sh -->

The system SHALL execute custom ECC installation using scripts under [harness/agy-script/install-agy.sh](file:///d:/dev/agy-os/harness/agy-script/install-agy.sh), applying non-destructive manifest overlays, performing Fail-Fast physical installation compliance verification via [verify-installation-agy.js](file:///d:/dev/agy-os/harness/agy-script/scripts/verify-installation-agy.js), and enforcing token budget governance.

#### Scenario: Executing custom ECC installation script
- **WHEN** the user or harness initiates custom ECC installation for Objective 02
- **THEN** the custom installer script [install-agy.sh](file:///d:/dev/agy-os/harness/agy-script/install-agy.sh) located in [harness/agy-script/](file:///d:/dev/agy-os/harness/agy-script/) is executed via Git Bash (`bash`)
- **AND** ECC subagents, rules, workflows, skills, and hooks are installed into designated target locations inside [.agents/](file:///d:/dev/agy-os/.agents/) without overwriting upstream [ECC](file:///d:/dev/agy-os/ECC) reference files

#### Scenario: Applying non-destructive manifest overlays
- **WHEN** the installation plan is resolved by [install-apply-agy.js](file:///d:/dev/agy-os/harness/agy-script/scripts/install-apply-agy.js)
- **THEN** custom manifest overlays from [harness/manifests/](file:///d:/dev/agy-os/harness/manifests/) are deep-merged with base manifests from `ECC/manifests/`
- **AND** original base manifest files in upstream [ECC/manifests/](file:///d:/dev/agy-os/ECC/manifests/) remain completely unaltered

#### Scenario: Fail-Fast physical installation verification script
- **WHEN** the custom installation pipeline finishes writing assets to disk
- **THEN** the verification script [verify-installation-agy.js](file:///d:/dev/agy-os/harness/agy-script/scripts/verify-installation-agy.js) checks physical file presence across all 6 item kinds (`rules` in `.agents/rules/`, `agents` in `.agents/plugin/ecc/agents/`, `commands` in `.agents/workflows/`, `hooks` at `.agents/hooks.json`, `skills` in `.agents/skills/`, `platform` in `.agents/plugin/ecc/platform/`)
- **AND** execution IMMEDIATELY fails with exit code 1 if any discrepancy or missing item is detected

#### Scenario: Token budget governance & rollback teardown
- **WHEN** customization token utilization is audited after installation
- **THEN** total prompt token footprint is verified to be maintained strictly within the **85% – 95%** target threshold
- **AND** manual user confirmation is strictly required before executing [uninstall-agy.sh](file:///d:/dev/agy-os/harness/agy-script/uninstall-agy.sh) if token usage exceeds 95%

<!-- entities: OpenSpecFramework, SubtreeIsolation -->
<!-- enforced: frameworks/openspec/AGENTS.md -->

The system SHALL maintain complete isolation of the OpenSpec framework engine, configurations, workflow definitions, rules, and assets within the designated [frameworks/openspec](file:///d:/dev/agy-os/frameworks/openspec) (`d:/dev/agy-os/frameworks/openspec`) subtree, ensuring framework-specific state and logic do not leak into the root harness or target repository.

#### Scenario: Scaffolding OpenSpec framework subtree
- **WHEN** the OpenSpec framework integration is initialized or updated
- **THEN** all OpenSpec CLI components, specifications, workflows, and scripts are placed strictly within [frameworks/openspec](file:///d:/dev/agy-os/frameworks/openspec)
- **AND** no OpenSpec internal engine artifacts pollute the root harness workspace [agy-os](file:///d:/dev/agy-os) outside `frameworks/openspec/`

#### Scenario: Maintaining root vs framework boundary
- **WHEN** executing spec-driven commands or workflows inside the OpenSpec framework
- **THEN** workspace context is scoped strictly to [frameworks/openspec](file:///d:/dev/agy-os/frameworks/openspec)
- **AND** read/write operations for framework artifacts remain strictly isolated within `frameworks/openspec/`

- **THEN** the workflow generates a unified diff or patch file detailing the proposed changes
- **AND** saves the generated patch file strictly inside [frameworks/openspec/harness/patches/](file:///d:/dev/agy-os/frameworks/openspec/harness/patches/)

#### Scenario: Preventing direct target repository modification
- **WHEN** any OpenSpec subagent or workflow attempts to modify, create, or delete a file in [website](file:///d:/CLAUDE-PROJECT/website)
- **THEN** the operation is blocked by workspace boundary rules
- **AND** direct filesystem mutation on target repository [website](file:///d:/CLAUDE-PROJECT/website) is rejected

## 3. Process Flow

1. **Step 1 — Custom ECC Installation & Harness Bootstrapping**: Execute [install-agy.sh](file:///d:/dev/agy-os/harness/agy-script/install-agy.sh) using Git Bash (`bash`), deep-merge manifest overlays from [harness/manifests/](file:///d:/dev/agy-os/harness/manifests/), run post-install transformation [post-install-agy.js](file:///d:/dev/agy-os/harness/agy-script/post-install-agy.js), and verify installation compliance via Fail-Fast script [verify-installation-agy.js](file:///d:/dev/agy-os/harness/agy-script/scripts/verify-installation-agy.js).
2. **Step 2 — Discovery & Isolation Setup**: Audit workspace roots [agy-os](file:///d:/dev/agy-os) and [frameworks/openspec](file:///d:/dev/agy-os/frameworks/openspec). Verify subtree boundaries, path invariants, and ensure `.agents` assets and workflow definitions are properly scoped within `frameworks/openspec/`.
3. **Step 3 — Specification & Change Proposal**: Use OpenSpec CLI / workflows to formulate spec-driven change proposals (`proposal.md`, delta specs) within `frameworks/openspec/`, aligning requirements with [docs/PRD.md](file:///d:/dev/agy-os/docs/PRD.md).
4. **Step 4 — Patch Staging & Execution**: Execute implementation steps and output all target repository code changes as `.patch` files staged in [frameworks/openspec/harness/patches/](file:///d:/dev/agy-os/frameworks/openspec/harness/patches/) without modifying target repository [website](file:///d:/CLAUDE-PROJECT/website) directly.
5. **Step 5 — Verification & Compliance Audit**: Run verification audits to confirm physical installation compliance, zero `PRD.md` or `prompt.md` files in [docs/OBJ-02/](file:///d:/dev/agy-os/docs/OBJ-02/), forward-slash URI path compliance, and Git Bash environment adherence.
